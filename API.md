# API.md: обмен данными между core и web

Формат запросов и ответов менять только по общему согласию. Если в ответе нужно новое поле, сначала договариваемся, потом правим код.

## Общие договорённости

1. **Города** передаются как `{"cities": [[x, y], ...]}`. Их от 3 до 50, координаты это числа, совпадающих городов быть не должно. Города нумеруются **с нуля** везде: в API, на холсте и в событиях.
2. **Имена параметров:** `n_ants`, `alpha`, `beta`, `rho`, `q`, `n_iter`, `seed`, `variant` (`"AS"` или `"MMAS"`).
3. **Маршрут** это список номеров городов без повторов. Он замкнут неявно: после последнего города идёт первый, и первый номер в конце списка не повторяется.
4. В JSON попадают только обычные `int`, `float` и `list`, типы numpy не допускаются.

## Сессия

Состояние (задача и движок) хранится на сервере. Идентификатор сессии клиент получает в ответе `POST /api/instance` (поле `session_id`) и присылает в каждом следующем запросе в заголовке:

```
X-Session-Id: <session_id>
```

Если сервер перезапустили (при `debug=True` это происходит после каждого сохранения файла), сессия пропадает. Тогда запросы возвращают `404` с `"code": "no_session"`. Страница в этом случае пишет, что сессия устарела, и при следующем нажатии «Шаг» создаёт задачу заново.

## Ошибки

Любая ошибка приходит как JSON с подходящим HTTP-кодом, без трассировки:

```json
{"error": "Параметр «ρ (rho)» должен быть в диапазоне (0; 1].", "code": "bad_request"}
```

| Код | `code` | Когда возникает |
|---|---|---|
| 400 | `bad_request` | неверные данные или параметры |
| 400 | `no_instance` | `/api/init` вызван раньше `/api/instance` |
| 400 | `no_engine` | `/api/step` или `/api/ant_step` вызван до `/api/init` или после `/api/reset` |
| 400 | `not_supported` | запрошен вариант алгоритма, которого ещё нет в ядре (`MMAS`) |
| 404 | `no_session` | неизвестный или устаревший `X-Session-Id` |
| 500 | `internal` | непредвиденная ошибка сервера |

## Эндпоинты

| Метод и путь | Что делает |
|---|---|
| `GET /` | отдаёт страницу |
| `POST /api/instance` | создаёт задачу |
| `POST /api/init` | принимает параметры и создаёт движок |
| `POST /api/step` | выполняет одну итерацию и возвращает снапшот |
| `POST /api/ant_step` | делает один шаг одного муравья и возвращает событие |
| `POST /api/reset` | сбрасывает движок |
| `POST /api/run` | выполняет k итераций за один запрос (пока не реализован) |

### `POST /api/instance`

В запросе либо случайная задача, либо свои города:

```json
{"n": 20, "seed": 42}
```
```json
{"cities": [[100, 200], [350, 120], [410, 300]]}
```

Поле `seed` необязательно: если его нет, сервер выберет значение сам и вернёт в ответе. При одинаковых `n` и `seed` получается одна и та же задача. Если в запросе были `cities`, то `seed` в ответе равен `null`.

Ответ `200`:

```json
{"session_id": "kP3x...", "n": 20, "cities": [[512, 88], ...], "seed": 42}
```

Новая задача сбрасывает движок в этой сессии.

### `POST /api/init`

Все поля необязательны. Если поля нет или оно пустое, берётся значение по умолчанию.

| Поле | Допустимые значения | По умолчанию |
|---|---|---|
| `n_ants` | целое, 1…500 | число городов |
| `alpha` | число, 0…10 | 1 |
| `beta` | число, 0…10 | 3 |
| `rho` | число, (0; 1] | 0.5 |
| `q` | число, (0; 10⁶] | 1 |
| `n_iter` | целое, 1…10000 | 200 |
| `seed` | целое, 0…2³²−1 | выбирает сервер |
| `variant` | `"AS"` или `"MMAS"` | `"AS"` |

```json
{"n_ants": 20, "alpha": 1, "beta": 3, "rho": 0.5, "q": 1, "n_iter": 100}
```

В ответе `200` приходят применённые параметры (с подставленными значениями, в том числе `seed`) и снапшот итерации 0:

```json
{"params": {"n_ants": 20, "alpha": 1.0, "beta": 3.0, "rho": 0.5, "q": 1.0,
            "n_iter": 100, "seed": 1873456, "variant": "AS"},
 "n_cities": 20,
 "snapshot": {"iteration": 0, "tau": [[...]], "tours": [], "lengths": [],
              "iter_best_length": null, "best_tour": [], "best_length": null, "time_ms": 0.0}}
```

### `POST /api/step`

Тело запроса не нужно. Метод выполняет **одну итерацию целиком** и возвращает снапшот. Если перед этим были шаги муравья (`/api/ant_step`), сначала **доигрывается текущая итерация**, а новая не начинается.

Сервер не останавливает счёт на `n_iter`, остановкой управляет клиент.

### Снапшот итерации

```json
{
  "iteration": 17,
  "tau": [[0.0, 1.2, ...], ...],
  "tours": [[0, 3, 1, ...], ...],
  "lengths": [412.3, 430.1, ...],
  "iter_best_length": 412.3,
  "best_tour": [0, 3, 1, ...],
  "best_length": 405.8,
  "time_ms": 12.4
}
```

| Поле | Что означает |
|---|---|
| `iteration` | номер выполненной итерации (0 значит «до первого шага») |
| `tau` | матрица феромона n×n, симметричная, с четырьмя значащими цифрами от максимума (см. ниже) |
| `tours` | маршруты всех муравьёв на этой итерации |
| `lengths` | длины этих маршрутов (с учётом возврата в первый город) |
| `iter_best_length` | лучшая длина на этой итерации |
| `best_tour`, `best_length` | лучший маршрут за всё время и его длина |
| `time_ms` | время итерации на сервере |

**Итерация 0.** В снапшоте `tours = []`, `lengths = []`, `iter_best_length = null`, `best_tour = []`, `best_length = null`, `time_ms = 0`. Клиент должен уметь с этим работать.

### `POST /api/ant_step`

Тело запроса не нужно. Метод возвращает **следующее событие** текущей итерации. Когда итерация закончилась (пришло событие `update`), следующий вызов начинает новую.

Порядок событий внутри итерации: для каждого муравья `n − 1` событий `move`, затем `tour_done`, а после всех муравьёв приходит `update`.

```json
{"phase": "move", "ant": 3, "current": 7, "partial_tour": [2, 9, 7],
 "candidates": [{"city": 12, "p": 0.23}, {"city": 4, "p": 0.11}], "chosen": 12}
```

- `partial_tour` это уже пройденная часть маршрута **вместе с текущим городом**, то есть `current` равен его последнему элементу.
- `candidates` это все ещё не посещённые города с вероятностями перехода `p` (в сумме примерно 1). Вероятности считает сервер, клиент их не пересчитывает.
- `chosen` это выбранный город.

```json
{"phase": "tour_done", "ant": 3, "tour": [2, 9, 7, 12, 4, 0, 1], "length": 412.3}
```

```json
{"phase": "update", "snapshot": { ...снапшот итерации... }}
```

> Формат `tour_done` в первоначальной договорённости не был описан, поэтому здесь предложен такой вариант: поля `ant`, `tour` и `length`. Его нужно подтвердить.

### `POST /api/reset`

Тело запроса не нужно. Метод удаляет движок, а задача остаётся. Повторный вызов безопасен: для неизвестной сессии тоже вернётся `200`. Ответ: `{"ok": true}`. После сброса следующим должен идти `/api/init`.

## Как веб подключён к ядру

Сервер работает с настоящими классами из `core/`:

- `POST /api/instance` создаёт `TSPInstance`. Для запроса `{"n", "seed"}` используется `TSPInstance.random(n, seed)`, поэтому одинаковые `n` и `seed` дают ту же задачу, что в ядре и в экспериментах. Файл, сохранённый методом `TSPInstance.save_json`, открывается на странице без доработок.
- `POST /api/init` сначала проверяет параметры сам (чтобы показать понятные сообщения), а затем создаёт `ACOParams(**params)`, то есть проверки ядра работают как запасные.
- Движок создаётся как `Engine(instance, params)`, где `instance` это `TSPInstance`, а `params` это `ACOParams`.

**Пока в `core/` нет класса `ACO`,** роль `Engine` играет переходник `web/core_engine.py`. Он собирает Ant System из `compute_choice_info`, `construct_tour` и `compute_nn_tour_length`, а феромон хранит и обновляет сам. Поддерживается только `variant = "AS"`, а `"MMAS"` даёт `400` с `"code": "not_supported"`.

Когда в ядре появится `ACO` с методами `initial_snapshot()`, `step()` и `ant_step()` и форматами, описанными выше, в `web/app.py` достаточно заменить одну строку, а `web/core_engine.py` удалить:

```python
from web.core_engine import CoreEngine as Engine
# заменить на
from core.aco import ACO as Engine
```

### Округление феромона в снапшоте (предложение, нужно согласовать)

Раньше было записано «округлять до 4 знаков после запятой». На крупных координатах это ломается: при τ₀ = m / C_nn и добавке 1/L значения порядка 10⁻⁴…10⁻² теряют всю структуру. Переходник округляет до **четырёх значащих цифр от максимума матрицы** (функция `round_tau` в `web/core_engine.py`). То же предлагается делать в настоящем `ACO`.
