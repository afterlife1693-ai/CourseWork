# API.md — контракт между `core/` (A) и `web/` (B)

Менять этот файл и форматы **только вдвоём**: нужно новое поле — сначала договориться, потом править код.

## Общие договорённости

1. **Города:** `{"cities": [[x, y], ...]}`, от 3 до 50 штук, координаты — числа, совпадающих городов нет. Города нумеруются **с нуля** везде (в API, на холсте, в событиях).
2. **Имена параметров:** `n_ants`, `alpha`, `beta`, `rho`, `q`, `n_iter`, `seed`, `variant` (`"AS"` / `"MMAS"`).
3. **Маршрут** — список номеров городов без повторов; замкнут неявно (после последнего идёт первый), последний номер **не** дублируется.
4. В JSON — только обычные `int` / `float` / `list` (не типы numpy).

## Сессия

Состояние (задача и движок) хранится на сервере. Идентификатор сессии клиент получает в ответе `POST /api/instance` (поле `session_id`) и присылает во всех следующих запросах в заголовке:

```
X-Session-Id: <session_id>
```

Если сервер перезапустили (при `debug=True` это происходит при каждом сохранении файла), сессия пропадает: запросы вернут `404` с `"code": "no_session"`. Страница в этом случае пишет «сессия устарела» и пересоздаёт задачу при следующем «Шаге».

## Ошибки

Любая ошибка — JSON и подходящий HTTP-код, без трассировки:

```json
{"error": "Параметр «ρ (rho)» должен быть в диапазоне (0; 1].", "code": "bad_request"}
```

| Код | `code` | Когда |
|---|---|---|
| 400 | `bad_request` | неверные данные или параметры |
| 400 | `no_instance` | `/api/init` до `/api/instance` |
| 400 | `no_engine` | `/api/step`, `/api/ant_step` до `/api/init` (или после `/api/reset`) |
| 404 | `no_session` | неизвестный или устаревший `X-Session-Id` |
| 500 | `internal` | непредвиденная ошибка сервера |

## Эндпоинты

| Метод и путь | Что делает | Неделя |
|---|---|---|
| `GET /` | отдаёт страницу | 1 |
| `POST /api/instance` | создаёт задачу | 1 |
| `POST /api/init` | принимает параметры, создаёт движок | 1 |
| `POST /api/step` | одна итерация, возвращает снапшот | 1 |
| `POST /api/ant_step` | один шаг одного муравья (на неделе 1 — заглушка) | 1 |
| `POST /api/reset` | сброс движка | 1 |
| `POST /api/run` | k итераций за запрос | 2 |

### `POST /api/instance`

Запрос — либо случайная задача, либо свои города:

```json
{"n": 20, "seed": 42}
```
```json
{"cities": [[100, 200], [350, 120], [410, 300]]}
```

`seed` необязателен (сервер выберет сам и вернёт). Одинаковые `n` и `seed` дают одинаковую задачу. Если в запросе были `cities`, `seed` в ответе — `null`.

Ответ `200`:

```json
{"session_id": "kP3x...", "n": 20, "cities": [[512, 88], ...], "seed": 42}
```

Новая задача сбрасывает движок сессии.

### `POST /api/init`

Все поля необязательны; пустое или отсутствующее поле — значение по умолчанию.

| Поле | Допустимо | По умолчанию |
|---|---|---|
| `n_ants` | целое, 1…500 | число городов |
| `alpha` | число, 0…10 | 1 |
| `beta` | число, 0…10 | 3 |
| `rho` | число, (0; 1] | 0.5 |
| `q` | число, (0; 10⁶] | 1 |
| `n_iter` | целое, 1…10000 | 200 |
| `seed` | целое, 0…2³²−1 | выбирается сервером |
| `variant` | `"AS"` или `"MMAS"` | `"AS"` |

```json
{"n_ants": 20, "alpha": 1, "beta": 3, "rho": 0.5, "q": 1, "n_iter": 100}
```

Ответ `200` — применённые параметры (с подставленными значениями, в том числе `seed`) и снапшот итерации 0:

```json
{"params": {"n_ants": 20, "alpha": 1.0, "beta": 3.0, "rho": 0.5, "q": 1.0,
            "n_iter": 100, "seed": 1873456, "variant": "AS"},
 "n_cities": 20,
 "snapshot": {"iteration": 0, "tau": [[...]], "tours": [], "lengths": [],
              "iter_best_length": null, "best_tour": [], "best_length": null, "time_ms": 0.0}}
```

### `POST /api/step`

Тело не нужно. Выполняет **одну итерацию целиком** и возвращает снапшот. Если перед этим были шаги муравья (`/api/ant_step`), сначала **доигрывается текущая итерация**, а не начинается новая.

Сервер не останавливает счёт на `n_iter` — остановкой управляет клиент.

### Снапшот итерации

```json
{
  "iteration": 17,
  "tau": [[0.0, 1.2, ...], ...],
  "tours": [[0, 3, 1, ...], ...],
  "lengths": [412.3, 430.1, ...],
  "iter_best_length": 412.3,
  "best_tour": [0, 3, 1, ...],
  "best_length": 405.8,
  "time_ms": 12.4
}
```

| Поле | Смысл |
|---|---|
| `iteration` | номер выполненной итерации (0 — до первого шага) |
| `tau` | матрица феромона n×n, симметричная, округлена до 4 знаков |
| `tours` | маршруты всех муравьёв этой итерации |
| `lengths` | их длины (замкнутые маршруты) |
| `iter_best_length` | лучшая длина этой итерации |
| `best_tour`, `best_length` | лучший маршрут за всё время |
| `time_ms` | время итерации на сервере |

**Итерация 0:** `tours = []`, `lengths = []`, `iter_best_length = null`, `best_tour = []`, `best_length = null`, `time_ms = 0`. Клиент обязан это переносить.

### `POST /api/ant_step`

Тело не нужно. Возвращает **следующее событие** текущей итерации; когда итерация закончена (пришёл `update`), следующий вызов начинает новую.

Порядок событий итерации: для каждого муравья `n − 1` событий `move`, затем `tour_done`; после всех муравьёв — `update`.

```json
{"phase": "move", "ant": 3, "current": 7, "partial_tour": [2, 9, 7],
 "candidates": [{"city": 12, "p": 0.23}, {"city": 4, "p": 0.11}], "chosen": 12}
```

- `partial_tour` — уже пройденная часть, **включая** текущий город (`current` — его последний элемент);
- `candidates` — все ещё не посещённые города с вероятностями перехода (`p`, сумма ≈ 1); вероятности считает сервер, клиент их не пересчитывает;
- `chosen` — выбранный город.

```json
{"phase": "tour_done", "ant": 3, "tour": [2, 9, 7, 12, 4, 0, 1], "length": 412.3}
```

```json
{"phase": "update", "snapshot": { ...снапшот итерации... }}
```

> `tour_done` в первоначальной договорённости был описан только словами — формат выше **предложен B, нужно подтвердить у A** (поля `ant`, `tour`, `length`).

### `POST /api/reset`

Тело не нужно. Удаляет движок, задача остаётся. Идемпотентно: для неизвестной сессии тоже `200`. Ответ: `{"ok": true}`. Следующим вызовом должен быть `/api/init`.

## Как подключить настоящий `ACO` (неделя 2)

В `web/app.py` одна строка:

```python
from web.mock_aco import MockACO as Engine
# ->
from core.aco import ACO as Engine
```

Движок создаётся как `Engine(cities, params)`, где `params` — словарь из ответа `/api/init`. Нужны методы `initial_snapshot()`, `step()`, `ant_step()` с форматами, описанными выше. Если конструктор настоящего `ACO` принимает другое (`TSPInstance`, `ACOParams`) — переходник пишется в одном месте, в `api_init`.
